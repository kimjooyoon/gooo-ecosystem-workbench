# 공개 Gooo로 다음 조립까지 이어가기

Gooo 소스로 프로그램을 조립하고, 틀린 호출을 같은 작업장에서 다시 조립하려는 사용자를 위한 기록입니다.
0.6.23 공개 실행 파일로 계획 조회부터 전체 그래프 조립까지 진행합니다.
`construct` 첫 화면에서 어디까지 맞았고 다음에 무엇을 할지 읽을 수 있게 바꿨습니다.

## 최근 자료에서 고른 것

2026-10-10 KST에 Hacker News와 GeekNews를 읽고 관련 원문을 확인했습니다.
GitHub Trending은 조회했지만 저장소 목록이 반환되지 않아 순위를 판단에 쓰지 않았습니다.

| 원문 | Gooo에 적용한 판단 |
| --- | --- |
| [Michael Lynch, Anti-Patterns in Software Blogging](https://refactoringenglish.com/blog/anti-patterns-software-blogging/) · 2026-10-07 | 처음부터 대상과 얻을 결과를 보여주는 설명을 참고. 시작 안내는 공개 파일과 첫 명령을 먼저 제시하고, construct는 단계별 점수와 다음 작업을 먼저 출력 |
| [Meadows](https://github.com/lorezzed/meadows) | 언어의 그래프 JSON을 다른 도구가 사용하는 구성을 참고. 작업장이 컴파일러의 원본 계획을 읽어 입력과 호출 관계를 유지 |
| [Once](https://github.com/alex0ptr/once) | 명령 결과를 이어 사용하는 사용 흐름을 참고. 저장한 조립 결과를 다음 입력과 테스트에 재생하는 기존 기능을 공개 파일로 연결 |
| [tinyjsapp](https://github.com/tarwin/tinyjsapp) | 작은 배포 단위를 참고. 현재 Go 도구와 CLI 계약으로 이어가고 별도 데스크톱 프레임워크 도입은 보류 |

원문에서 배운 것을 Gooo 사용 흐름에 적용한 판단입니다. 해당 구현을 의존성으로 추가하지 않았습니다.
시간이 지나면 성공 결과를 그대로 믿는 캐시는 보류했습니다. 재사용할 때 원래 소스와 저장한 조립 기록을 확인합니다.

## 이번 변경

기존에는 여러 본문 조립에 개발 소스를 따로 빌드해야 했습니다. 공개 0.6.23에 계획·입력·저장 재생 흐름이
포함되어 같은 설치본으로 이어갈 수 있습니다. CI도 공개 Linux 파일을 받아 같은 소스를 확인합니다.
원래 보고서는 파일에 남기고 `construct --json`으로 전체 JSON을 표준 출력에 받을 수 있습니다.
표준 출력을 파싱하던 기존 도구는 이 옵션을 추가해야 합니다.

회차의 다음 작업 문장은 실제 Gooo 진단에서 읽어 기록합니다. Go 출력 코드가 새 조립 정책을 판단하지 않습니다.
원래 모델 호출, 이번 모델 연결 여부, 조립 중 평가, 마지막 별도 입력을 나눠 표시합니다.
기대값이 없으면 0/0과 미측정을 보여줍니다.

같은 후보 예제의 전체 출력 742줄을 13줄로 줄인 실행을 확인했습니다. 원래 호출 0/3과
모델 호출 2회도 요약에 남습니다. 후속 조립의 필드 9/9와 마지막 별도 입력의 필드 6/6을
합쳐 전체 언어의 정답률로 표현하지 않습니다. [원본 관측](../publication/public-input-workbench-20261010/README.md)을 공개합니다.

다시 조립하는 경로는 더 구현해야 합니다. 다음 목표는 지원 선택지를 늘리면서 원래 입력,
