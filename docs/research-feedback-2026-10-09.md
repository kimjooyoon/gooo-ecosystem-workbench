# 최근 도구에서 가져온 흐름과 줄인 절차

2026-10-09에 [Hacker News](https://news.ycombinator.com/),
[GeekNews](https://news.hada.io/), [GitHub Trending](https://github.com/trending)을
다시 읽고 아래 프로젝트 원문에서 적용할 범위를 골랐습니다. 순위와 별 개수를
품질 지표로 쓰지 않습니다. 이전 관측과 날짜가 같은 글도 별도 변경으로 남깁니다.

## 적용한 원리

[Matt Pocock의 skills](https://github.com/mattpocock/skills)는 작은 도구를 함께
쓰는 구성, 공유 용어, 테스트 피드백을 강조합니다. 작업장에서도 조립과 반례
반복 사이에 파일들을 다시 지정하는 절차를 줄였습니다. `construct --assembly`
옵션으로 원래 폴더 하나를 넘기면 기존 반복 기능을 사용합니다.

[Addy Osmani의 agent-skills](https://github.com/addyosmani/agent-skills)는 작업
분해와 필요할 때 참고 자료를 읽는 흐름을 보여줍니다. Gooo에는 실패 입력의
짧은 목록과 원본 파일을 함께 남기는 방식을 적용했습니다. 다음 도구가 원본
기대값과 소스 사례를 읽으며, 요약만으로 새 기대값을 만들지 않습니다.

[Alibaba의 Open Code Review](https://github.com/alibaba/open-code-review)는
결정론적인 처리와 모델 판단의 역할을 나눕니다. Gooo에서 수와 입력·기대값의
보존, 실행과 재생은 기존 컴파일러가 맡고 모델은 선언된 후보의 순서를 제안합니다.
별도 리뷰 에이전트나 승인을 요구하는 절차는 추가하지 않았습니다.

HN에서 소개된 [Once](https://github.com/alex0ptr/once)는 명령 결과를 일정 시간
재사용합니다. Gooo에는 저장된 결과를 다음 작업에 가져오는 원리를 참고합니다.
현재 반례 반복은 조립 조건이 바뀌므로 매 회차 새로 조립하고 중복 시도도 셉니다.
시간만으로 이전 검사나 모델 결과를 재사용하는 캐시는 도입하지 않았습니다.

## 이번에 줄인 것

사용자가 소스·활동·조립용 사례·호출 사례를 다시 짝짓는 절차를 줄였습니다.
이전 모델을 자동으로 다시 사용하는 숨은 설정도 두지 않습니다. 후속 명령에서
모델을 생략하면 고정 순서로 진행하며 모델을 연결하려면 파일을 명시합니다.

원래 실행과 새 실행은 따로 보관합니다. 반례 파일을 준비한 상태와 실제 다음
조립에서 읽은 상태를 구분합니다. 실패·취소 뒤에도 진행 기록이 남습니다.
반례 수집은 기대값 없는 행에 점수를 붙이지 않습니다. 현재 body-compose는 호출
기대값을 요구하므로 이 연결의 실제 예제도 기대값을 제공합니다. 모순된 기대값은 유지합니다.

## 범위와 다음 일

새 연결은 루트 레코드 활동 하나에서 시작합니다. 여러 패키지에는 기존
`construct --workspace`가 있습니다. 저장한 여러 활동의 사례를 옮기려면
루트 입력과 중간 활동 입력을 구분하는 규칙과 실제 재현 자료가 더 필요합니다.

같은 작은 프로그램의 결과를 전체 생성 정확도로 일반화하지 않습니다.
처음 정한 입력에서 필드·호출을 몇 개 맞혔는지, 다음 조립이 몇 번 시도했는지,
선택이 끝난 뒤 다른 입력을 몇 개 맞혔는지를 각각 설명합니다.
낮은 전이 성능의 자체 모델도 그대로 사용해 결과를 공개합니다.
