# 최근 자료에서 고른 다음 사용 흐름

2026-10-09 Hacker News와 GeekNews의 목록을 읽고 원문을 확인했습니다.
GitHub Trending 기본 페이지는 저장소 목록을 반환하지 않았고, Go 일간 페이지에는
3주 전 수집 표시가 있었습니다. 현재 순위를 근거로 채택하지 않습니다.

이번에는 저장한 조립 결과를 두 활동의 실제 실패에 연결했습니다. 첫 활동의
조립 사례가 맞아도 마지막 결과는 틀릴 수 있으므로, 마지막 결과의 반례를 원래
루트 입력과 함께 다음 생성에 넘깁니다. [바로 실행하는 예제](../examples/assembly-graph-feedback/README.md).

| 읽은 자료 | 가져온 원리와 적용 | 이번에 늘리지 않은 것 |
| --- | --- | --- |

| [Deno, 10월 9일 발표](https://deno.com/blog/cloudflare) | 기존 생태계와 연결한 사용 경험, 실행·배포까지 이어지는 도구 범위. Gooo도 공개 Go 생성·저장 재생 경로 유지 | 새로운 호스팅 서비스·전용 런타임 도입 |

위의 Gooo 적용은 원문을 읽은 뒤 내린 설계 판단입니다. 각 프로젝트의 전체 접근을
재현했다는 의미로 사용하지 않습니다. 별도 외부 코드를 가져오지 않았습니다.

## 언어 관점의 구분

소스의 의도·후보·사례는 `.gooo`에 있습니다. 모델은 조립할 식의 순서를 제안합니다.
컴파일러는 선택한 본문을 실제 Go로 만들고, 마지막 활동을 실행합니다. 후속 행동과
반례 선택은 기존 Gooo 정책이 결정하고 Go 도구가 파일·명령을 연결합니다.

이번 확장은 입력 전용 CLI 개선 이후의 별도 작업이며 공개 0.6.22에서 실행됩니다.
기대값을 선언한 호출 사례를 사용합니다. 추가 루트가 있는 그래프에서 중간 값을
원래 입력으로 취급하는 변환은 넣지 않았습니다. 이런 그래프는 기존 전체 조립
경로에 원래 루트 사례를 제공해야 합니다.

작은 연결 그래프의 유한 사례 결과, 새 모델 호출 수, 원본 반례가 실제 소비됐는지를
관측합니다. 일반 구현 확률이나 모델의 전체 정확도로 해석하지 않습니다.
