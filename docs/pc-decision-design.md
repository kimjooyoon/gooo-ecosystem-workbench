# 우리 PC에서 만들고 쓰는 Gooo 판단 모델

Gooo가 소스에서 가능한 부품과 연결을 준비합니다. 작은 자체 모델은 어느 후보부터
확인할지 제안하고, Gooo는 타입·허용 후보·실제 사례를 확인해 프로그램을 조립합니다.
모델의 출력은 기존 후보 라벨과 점수, 판단 보류입니다. 자유로운 토큰 생성은 이 설계에서
사용하지 않습니다. 의도와 안정 ID는 Gooo 소스에 남습니다.

## 현재 구현과 PC 비용

[Go 학습 코드](../experiments/path-chooser)와 [자체 가중치](../models/per-choice-20261010)는
외부 기반 모델 없이 만든256→48→8 배열 신경망입니다. 같은12,728개 매개변수를 선택마다
재사용합니다. 현재 입력은 정규화 소스 특징64개와 위치를 보존한 문장 특징192개입니다.
한글·영어 문장을512바이트 안에서 모두 읽으며 입력 일부를 잘라서 판단하지 않습니다.
허용한 선택 수는 기존 경로 계약에서1..16이고, 조합 확인은 별도 한도가 있습니다.

CPU Go 학습·내보내기·평가 전체0.86초, 최대 RSS14,401,536바이트였습니다.
QAT 가중치 파일2,759바이트, 상주 텐서12,896바이트와 scale8바이트,
worker별 작업 배열1,248바이트입니다. SDK 판단은 한 곳 약10µs였고 GPU는 사용하지
않았습니다. 모델 메모리와 Go 프로세스·컴파일·기록 메모리는 각각 측정합니다.
FP32보다 작은 파일을 얻었지만 이번 추론은 약간 느렸습니다.

## 모델 성적과 프로그램 성적

학습은 여섯 소스 특징에서 작성한48개 문장입니다. 같은 소스 특징의 다른24개 문장에서
QAT 라벨은15개 일치, 보류는5개였고 높은 점수의 오답도1개 있었습니다.
이는 문장·후보 판단의 관측입니다. 새 소스 전체에 대한 정답률은 별도입니다.

그 후 컴파일러366의 세 선택 프로그램에서 모델은 세 번, 합계35,292ns 판단했습니다.
분기와 비교·뺄셈 피연산자 모두 reverse를 제안했고, 점수는0.809~0.914였습니다.
실제 별도 입력은2/3만 맞았습니다. 음수-5에서0 대신-10을 반환했습니다.
같은 프로그램의 고정 순서는2회 조립 시도로3/3을 맞혔습니다.
모델 경로의 저장 재실행은 새 추론 없이 원래2/3를 유지했습니다.

이 실패 하나를 다음 조립의 사례로 복사했습니다. 이미 소비한 사례로 표시하고,
새 입력0·1·-1·5·-7을 별도 평가했습니다. Gooo는 모델 호출 없이 고정 순서의 두 조합을
확인해5/5를 맞혔고, 저장 재실행도5/5였습니다. 가중치와 원래2/3 결과는 유지했습니다.
기존 기대값을 가진 실패에서 이어간 한 함수의 유한 실험입니다.

[원본 소스·사례·입력 지문·실행·피드백 기록](https://raw.githubusercontent.com/wiki/kimjooyoon/meta-ontology-go/observations/per-choice-native-20261010/README.md)

## 어떤 선택을 학습할지

같은 세 선택 함수에서 가능한8개 조합을 모두 관측하는
[Go 도구](../experiments/path-outcomes/PLAN.md)를 추가했습니다. 함수의 절댓값 동작을
요청하는9개 사례를 소비해 보니 두 조합이 모두 맞았습니다. 각 지점에서 가능한 선택만
따로 모으면 네 조합이 생기고, 그중 둘은 틀립니다. 분기 방향과 비교 방향을 함께
고려해야 하는 예입니다. 두 정답 조합을 통째로 남겨 다음 모델 학습에 쓸 수 있게 했습니다.

8×9개 결과는 별도 네이티브 실행과72개 모두 일치했습니다. 이것은 코드 투영의 일치
검사이며, 기능을 만족한 후보는8개 중2개입니다. 자료 생성 전체0.96초, 최대 RSS 약71.5MiB,
조합 평가 자체는 약0.19ms였습니다. 기대값을 소비한 자료이고 가중치는 갱신하지 않았습니다.
[원본·정답 조합·범위](../publication/compatible-path-targets-20261010)를 함께 공개합니다.

그 자료를 실제 소형 모델 학습에도 연결했습니다. 같은 기존 FP32 가중치에서 두 모델을
같은 횟수로 학습했습니다. 기존 문장 자료만 이어 배운 모델은 새 호출 입력6/11,
정답 조합 자료를 함께 배운 모델은11/11을 통과했습니다. 이전 모델도 같은 입력에서6/11이었습니다.
저장 재실행은 각각 같은 결과를 유지했고 새 추론은0회였습니다.

반면 기존24개 문장 평가는 이전 모델15/24, 문장 학습 모델18/24, 조합 학습 모델13/24였습니다.
한 함수에서 나아진 동작과 다른 판단에서의 손실을 함께 봅니다. 가중치는2,759바이트,
두 모델의 학습·내보내기·평가 전체는1.18초, 최대 RSS 약15.6MiB였습니다.
[실험 가중치와 사용법](../models/joint-path-20261010),
[비교 원본](../publication/joint-path-learning-20261010)을 공개합니다.

내부 의도에는 별도 문제가 남았습니다. 소스 힌트는 “음수인지 비교”인데 세 모델의
실제 조건은 모두 `0 < input`이었습니다. 실행 뒤 추가한 -1·0·1의 진릿값 진단은1/3만
일치했습니다. 새 모델은 다른 분기 선택을 통해 최종 출력은 맞혔습니다. 이 문장 힌트는
아직 강제되는 조립 조건이 아니므로, 함수 결과와 중간 판단의 의도 일치를 각각 기록합니다.
다음 언어 작업에서는 중간 조건의 기대값도 Gooo 소스에 명시하고 검사할 수 있게 해야 합니다.

## 다음 설계에서 먼저 확인할 것

현재 크기부터 이어갑니다. 모델 크기와 학습량을 늘리기 전에 다음을 비교합니다.

1. **후보의 차이를 입력으로 보여 주기.** 선택 종류·타입·연산자와 허용한 각 후보의
   구조를 표현해 점수화합니다. 현재 ABI에 후보별 새 표현을 구현했다는 주장은 없습니다.
2. **소스 계열부터 나누기.** 같은 코드의 다른 문장, 다른 코드 구조, 한영 표현을
   각각 평가합니다. 소스 계열 분할 이후에 문장을 늘려 같은 원본이 양쪽에 들어가지 않게 합니다.
3. **보류 점수 확인하기.** 보정용 자료와 최종 평가를 나눕니다. 점수가 높아도 틀린
   사례 수와 보류한 수를 함께 보여 줍니다. 현재 점수는 보정한 정답 확률로 해석하지 않습니다.
4. **선택의 상호작용 학습을 넓히기.** 한 함수의 정답 조합 학습을 실제 연결했고 기존 문장 성적의 하락도 관측했습니다.
   다른 소스 계열에서 같은 비교를 하고, 한 지점의 선택 성적과 조합 전체의 기능 성적을 나눕니다.
   실제 실패를 다음 조립에서 소비하면 그 사례를 새 평가 분모에서 제외합니다.

지표는 판단한 선택 수, 보류 수, 높은 점수의 오답, 사례별 실제 기능 결과,
확인하지 않은 경로, 추론 횟수와 PC 비용입니다. 하나의 완전성 숫자로 합치기 전에
각 분모와 소스·모델·사례 지문을 남깁니다. 후보 선택·테스트·정해진 순서의 후속 조립을
우리 컴퓨터에서 짧게 반복하는 방향입니다.
