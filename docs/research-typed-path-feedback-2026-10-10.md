# 작은 판단을 실제 언어 작업으로 연결하기

확인일: 2026-10-10 KST. 최근 Hacker News·GeekNews·GitHub의 사례에서
소개 글과 원문 구현을 함께 읽었습니다. 현재 Gooo의 실패 입력을 다시 쓰는 과정에
적용할 수 있는 작은 원리를 골랐습니다.

| 자료 | 가져온 원리 | 이번 적용 |
| --- | --- | --- |
| [pg-jev](https://github.com/realZachi/pg-jev) | 자연어 판단을 기존 SQL의 필터·선택 기능에 연결. 배열 위치와 배치 크기의 표현 한계도 기록 | 큰 자유 형식 출력보다 소스의 작은 선택 ID를 사용. 분기·변수 후보와 실제 값을 그대로 검사 |
| [Microsoft-Decision-1 발표](https://commandline.microsoft.com/microsoft-decision-1-model-foundry/) | 정해진 선택지의 점수와 표현·순서 변화의 안정성을 함께 다룸 | 자체 모델의 제안과 실행 결과를 따로 기록. 성공 확률 해석은 별도 보정 실험에 맡김 |
| [RAD Debugger](https://github.com/EpicGames/raddebugger) | 디버그 정보 형식과 이를 읽는 도구의 연결 | 컴파일러의 계획·원본 결과·저장 재생을 작업장이 계속 읽음 |

위 표는 외부 프로젝트를 참고한 설계 판단입니다. 이번 변경은 기존 Go 어댑터와
Gooo 정책으로 구현하며, 외부 모델의 성능 수치를 Gooo의 성과로 옮기지 않습니다.

## 뺀 규칙

이전 작업장의 `graph-next.gooo`는 typed 본문이 하나라도 있으면
`expand-joint-profile`로 멈췄습니다. dev 컴파일러가 해당 재조립을 지원한 뒤에도
이 규칙이 남아서 실제 가능한 작업을 막았습니다. 이제 Gooo가 원래 호출 반례를 고르고,
지정한 컴파일러가 계약과 지원 범위를 확인합니다.

원본 공개 0.6.23도 계속 확인합니다. 그 컴파일러가 지원하지 않는 재조립은 원래 오류를
기록합니다. 새 컴파일러를 자동으로 내려받거나 기존 영수증의 소스를 바꾸지는 않습니다.

## 연결한 검사

작업장은 v7 영수증의 typed 후보를 읽습니다. 후보 선택과 mask의 대응, 선언한 후보 공간,
시도 상한, 문서·계획 지문, 정확한 지역 사례 값을 검사하고 점수를 다시 셉니다.
레코드·식 탐색·빈칸과 섞인 경우에도 검사된 앞부분만 합산합니다.
타입 검사에서 거절된 후보에는 호출 점수를 붙이지 않습니다.
0 나눗셈 같은 네이티브 실패도 별도 기록으로 읽습니다.

소스의 의미와 저장된 프로그램의 동일성은 네이티브 컴파일러 재생이 확인합니다.
작업장의 JSON 재계수는 실행을 대신하지 않습니다. 초기 사례, 재조립에 쓴 호출 사례,
선택 뒤의 별도 사례도 분리합니다.

## 유지·보류

모델 생략 경로는 고정 순서로 이어갑니다. 기존 자체 QAT 모델의 작은 텐서는 계속 사용합니다.
소스의 선택 범위를 늘리는 실험과 한국어·영어 의도 표현의 안정성 검사를 우선합니다.
큰 모델 설치, 새 그래픽 디버거, 시간만으로 유효성을 판단하는 캐시는 보류합니다.
