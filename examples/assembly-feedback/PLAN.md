# 저장한 조립을 반례로 이어가기: 관측 전 계획

2026-10-09. 아래 입력과 기대값을 실제 실행 전에 정했습니다.

한 개의 레코드 활동에서 문구, 활성 상태, 입력 정수 보존의 세 후보를 고릅니다.
소스의 첫 사례는 `[0,false,"idle"]`입니다. 이 입력에서는 모든 후보가 같은
답을 내므로 소스 사례만 통과한 결과에 새로운 호출 입력이 필요합니다.

고정 순서와 기존 자체 소스 그래프 QAT 모델을 각각 한 번 사용해 `assemble`의
원본을 저장합니다. 모델 가중치, 문구, 후보 위치는 실행 결과에 맞춰 바꾸지 않습니다.
원본에 실패한 호출이 있으면 `construct --assembly`로 다음 조립에 넘깁니다.
모델 옵션을 생략한 후속 실행과 명시적으로 같은 모델을 연결한 후속 실행을 구분합니다.

후속 조립은 기존 Gooo 반례 정책과 전체 프로그램 시도 한도를 사용합니다.
소스 사례를 원래 입력·기대값 그대로 호출 형식으로 옮기고, 실패한 호출의
전체 원본 행을 추가합니다. 소스 본문과 소스 사례의 기대값은 그대로 둡니다.
각 회차는 새로 조립하며, 반복한 시도와 모델 호출도 다시 셉니다.

초기 관측은 호출 2개·필드 6개, 소스 사례 1개·필드 3개로 따로 셉니다.
시도 상한 8, 회차 상한 4에서 진행합니다. `holdout-cases.json`의 두 입력은
선택이 끝난 뒤 저장된 프로그램만 재생하며 반례로 넣지 않습니다.
입력 분리는 기록하지만 모델 학습 자료와의 독립성은 확인되지 않았습니다.

추가 확인: 준비됐지만 실행되지 않은 반례, 취소·실패 시 부분 기록,
입력만 있는 미채점 사례, 서로 모순되는 기대값, 큰 정수 9007199254740993,
원본 파일 변경과 지원 범위를 벗어난 그래프를 구분합니다.

목표는 사용자가 파일들을 다시 짝짓지 않고 저장된 결과로 다음 조립을
진행하는 것입니다. 사례를 충족하는 정도와 전체 언어 능력은 별도로 설명합니다.
