# 계산에 실패한 후보 다음으로 넘어가기

`source.gooo`는 예산 상한을 계산하는 함수입니다. 타입이 틀린 후보, 지역 예제에서
계산이 실패하는 후보, 부품 예제는 통과하지만 실제 호출에서 0으로 나누는 후보가
함께 있습니다. 실패한 이유를 남기고 다음 후보를 확인하는 예제입니다.

컴파일러 개발 소스 `3b762198b42d9ab552421b19519d3d4834b34ab3`가 필요합니다.
[빌드와 자동 반복 명령](../../docs/usage.ko.md#실행-중-계산-실패를-다음-조립에-반영하기).
현재 공개 0.6.15 실행 파일에는 실제 호출의 계산 실패를 이어가는 경로가 아직 없습니다.

| 실행 | 시도 | 지역 탈락 | 실행한 조합 | 그중 계산 실패 | 최종 평가 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 다섯 후보까지 | 5 | 2 | 3 | 1 | 1/4 |
| 여섯 후보까지 | 6 | 2 | 4 | 1 | 4/4 |
| 혼합 조립·고정 순서 | 48 | 16 | 32 | 8 | 4/4 |
| 혼합 조립·기존 모델 | 6 | 2 | 4 | 1 | 4/4 |

저장된 재실행은 과거 시도 수를 보존하고 새 모델 예측은 0회입니다.
고정 순서와 모델 순서는 같은 최종 소스를 얻었습니다. 모델은 레코드 후보 순서를
제안합니다. 빈칸은 선언 순서대로 확인합니다.

`graph.gooo`는 독립 활동과 의존 활동의 차이를 보여줍니다. 두 입력에서 기대한
출력 8개 중 6개가 맞고, 하나는 계산 실패, 하나는 앞선 실패 때문에 실행하지 못합니다.
`9007199254740993`도 원래 정수 그대로 남습니다. `graph-partial-expectations.json`은
같은 실행에서 일부 기대값만 지정한 별도 사례입니다. 점수는 6/6이지만 계산 실패와
의존 활동 중단은 남아 있으므로 완료로 안내하지 않습니다.

`all-faults.gooo`에서는 두 후보가 모두 실제 호출에 실패합니다. 선언한 공간을
모두 확인한 부분 결과를 남기고 저장된 이력도 그대로 재현합니다.

`adaptive-fault.gooo`는 처음에 `input / input`을 선택합니다. 평가에서 입력 0이
계산에 실패하면 Gooo가 그 입력과 기대값 1을 다음 조립 조건으로 추가합니다.
시도 한도를 늘린 세 번째 회차에 상수 1 구현을 고르고, 별도 정수 입력 3개를
모두 맞힙니다. 총 시도 수는 1 + 1 + 2 = 4입니다.

```sh
# 원본 실행 6개를 다시 집계하며 소스와 기대값을 확인합니다.
go run ./experiments/native-outcome-observe

# 그래프를 실제로 실행하고 결과로 다음 작업을 제안합니다.
mkdir -p out
./.gooo body-compose --source examples/caller-native-failure/graph.gooo \
  --cases examples/caller-native-failure/graph-cases.json --out out/fault-graph \
  > out/fault-graph.json
go run ./cmd/workbench diagnose --compiler ./.gooo \
  --input out/fault-graph.json --out out/fault-next
```

두 번째 명령 묶음은 먼저 `out` 폴더를 준비합니다. 출력 경로는 실행마다 새로 지정합니다.
현재 이 경로는 int64 `/`, `%`의 0 제수만 관측합니다. 취소, 시간 초과,
그 외 프로세스 실패는 원래 오류로 남습니다. [측정 원본과 범위](../../publication/native-outcomes-20261009/README.md).
