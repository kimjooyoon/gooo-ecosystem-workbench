# 같은 코드 부품에 다른 요구를 주면

2026-10-08 로컬 관측. 컴파일러는 깨끗한 소스
`e0d046503939883330eb37f998a2e0e8fc5154e5`, Go 1.27.1,
입력 해석은 `gooo-decision-runtime v0.2.26-experimental`을 사용했습니다.

앞선 자료는 같은 요구를 한국어와 영어로 표현했습니다. 이번에는 요구 자체를
바꿨습니다. 파일 이름을 그대로 반환하거나 접미사를 제거하기, 계산한 몫을
유지하거나 부호를 뒤집기, 계산한 재시도 여부를 쓰거나 항상 끄기 같은 선택입니다.
세 필드의 두 선택을 조합하면 프로그램마다 여덟 정책이 됩니다.

**3개 프로그램 × 8개 요구 조합 × 8개 선택지 배치 × 3개 표현 = 576행**입니다.
세 프로그램의 반복 변형이며, 576개의 독립 기능을 만들었다는 뜻으로 세지 않습니다.
요구를 바꿔도 코드 본문과 두 후보식, 그래프의 노드·뿌리·필드 ID가 유지되는지 검사합니다.
예상 결과는 별도 Go 함수로 계산하고, 컴파일러가 실제 후보를 검사해 선택한 값과 연결합니다.
원래의 수작업 사례도 이 함수와 일치해야 수집을 시작합니다.

## 요구 문장이 입력에서 하는 일

| 모델에 제공할 정보 | 서로 다른 전체 특징 배열 | 이 정보만 사용하는 결정론적 선택기의 자료 내 최대 충족 행 |
| --- | ---: | ---: |
| 코드 그래프와 요구 문장 | 576 | 576/576 |
| 같은 코드 그래프, 요구 문장을 같은 문자열로 치환 | 24 | 72/576 (12.5%) |

전체 float32 배열의 비트를 비교했습니다. 문장을 지운 각 그룹에는 여덟 정답이
각각 세 번씩 등장합니다. 그룹마다 하나의 답을 고르면 최대 세 행이 맞습니다.
선택지 위치나 코드 구조만 보고 모든 요구를 맞히는 지름길을 막은 자료입니다.
576/576은 실제 모델 점수가 아닙니다. 이 자료에서 입력이 정답들을 구별할 수 있는지
확인한 결과이며, 새 가중치를 학습하거나 자연어 일반화 성능을 측정하지 않았습니다.

Gooo로 작성한 평가 함수도 두 관측을 직접 읽었습니다. 전체 입력에는
`evaluate-chooser`, 문장을 지운 입력에는 `preserve-distinguishing-source-facts`를
반환했습니다. 평가 프로그램의 실행·재실행 기록을 함께 공개합니다.

## 조립한 프로그램도 실행해 보기

세 프로그램의 여덟 요구 조합을 각각 생성했습니다. 이 확인은 혼합 언어와 고정된
선택지 배치 한 가지를 사용합니다. 원래 조립 사례와 겹치지 않는 입력을 넣었습니다.

- 파일 이름: 다섯 입력 × 여덟 정책 = 40/40 결과 충족.
- 정수 나눗셈: 다섯 입력 × 여덟 정책 = 40/40. 큰 정수와 최솟값, 0인 분모 포함.
- 재시도: 여섯 입력 × 여덟 정책 = 48/48. 각 중단 사유와 시간 상한 포함.
- 저장한 조립의 재실행: 같은 128/128 결과 충족, 새 모델 호출 0회.

16개의 고유 입력을 정책별로 재사용한 128개 사례입니다. 생성과 재실행은 각각
128건이며 두 횟수를 합쳐 고유 입력 수로 세지 않습니다. 각 출력의 세 필드도
기대값과 직접 대조했습니다. 각 명령 내부의 반복 실행도 별도 새 사례로 세지 않습니다.
수집기는 실제 입력과 출력 JSON을 독립적으로 다시 비교하며 int64 정밀도를 보존합니다.
전 과정은 결정론 경로로 실행했습니다.

처음 네이티브 관측을 읽을 때 단일 입력을 복수 입력 배열로 가정한 수집기 오류가
발견됐습니다. 단일 `input`과 순서 있는 `inputs`를 구분한 뒤 전체 24개를 다시 실행했습니다.
공개 원본은 그 전체 실행과 재실행 결과입니다. 관측값이나 출처를 바꿨을 때 수집기가
거부하는 회귀 검사도 포함합니다.

## 원본과 재현

- `corpus-evidence.tar.gz`: 576개 Gooo 소스, 원본 그래프와 유한 검사 결과,
  전체·문장 제거 입력, 출처 목록. 약 5.3 MiB로 압축했습니다.
- `native-evidence.tar.gz`: 24개 조립과 별도 입력, 실제 실행 및 저장 재실행. 약 645 KiB.
- `corpus-index.json`, `native-summary.json`: 각 소스와 관측의 연결 및 개수.
- `full-feature-audit.json`, `ablated-feature-audit.json`: 배열별 정답 분포와 충돌.
- `assessment.gooo`, `*-assessment.json`: Gooo가 두 관측을 평가한 소스와 실행 기록.
- `SHA256SUMS`: 이 디렉터리의 공개 파일 해시.

두 번의 독립 수집에서 `audit-input.json`과 `corpus-index.json`은 바이트 단위로
같았습니다. 학습 예제는 압축 JSON으로도 제공하며 CI가 풀어 검사합니다.
[수집·네이티브 실행 명령](../../examples/graph-choice-corpus/README.md)을 사용합니다.

다음 학습에서는 프로그램 하나를 통째로 제외해 384행으로 학습하고 192행으로
평가하는 세 분할을 사용합니다. 같은 프로그램의 배치와 번역을 양쪽에 섞지 않습니다.
첫 선택, 정해진 시도 안의 완성도, 요구를 뒤집었을 때의 선택 변화와 필드별 결과를
따로 봅니다. 새 표현과 새 프로그램에서의 판단은 추가 자료로 확인할 과제입니다.
