# 정수 계산식과 레코드 선택을 같은 반복에 넣기

2026-10-09. 컴파일러 개발 소스 `de5aba5b5103dd6e2f1c73afc9c3e09c7b46ba08`에서
정수 `search hole`과 레코드 선택을 함께 조립했습니다. 작업장에는 새
`gooo/joint-construction/v2` 기록을 읽는 경로를 연결했습니다. 공개 0.6.12는
기존 레코드 조립을 지원하며, 이 새 혼합 조립에는 개발 컴파일러가 필요합니다.

지역 예제로는 둘 다 맞던 `input`과 `0`을 호출자의 실패로 구분합니다.
자체 그래프 모델은 레코드의 초기 순서를 고르고, 계산식은 소스 문법에서
정해진 순서로 살펴봅니다. 모델 가중치는 그대로 사용했습니다.

이번 자동 반복은 처음에 호출자 예제를 `0 → 0` 하나만 받았습니다.
평가에서 실패한 두 사례를 Gooo 규칙이 그대로 다음 조립 조건에 추가했습니다.
6회차, 총 25번의 프로그램 시도 끝에 모든 조립 조건을 충족했습니다.
각 회차는 새로 시작하므로 이 25번에는 반복해서 본 조합도 포함됩니다.

마지막에 따로 둔 네 입력은 **4/4**였고, 해당 호출자 조립 입력과 겹치지 않았습니다.
마지막 평가는 저장 조립을 재실행해 수행하며 새 모델 호출은 0회였습니다.
원래 기대값을 수정하지 않았습니다. 프로그램 한 개의 자동 반복 관측이며,
처음 모델 추천의 정답률이나 일반적인 자연어 구현 확률을 나타내지 않습니다.

`loop.tar.gz`에는 입력·정책 소스·회차별 원본 결과·반례 추가 기록·최종 재실행이
있습니다. `joint-loop.json`에서 회차와 시도 수, 준비한 반례의 실제 소비 여부,
최종 평가와 입력 중복 수를 볼 수 있습니다. 컴파일러 예제와 원본 직접 조립 관측은
[개발 소스](https://github.com/kimjooyoon/meta-ontology-go/tree/de5aba5b5103dd6e2f1c73afc9c3e09c7b46ba08/examples/caller-ir-search)에 있습니다.

원본 v2 기록 세 개는 `examples/joint-diagnostics/search.json.gz`,
`mixed-search.json.gz`, `mixed-search-replay.json.gz`에 보존했습니다.
회귀 테스트는 지역 계산식과 레코드의 실제 값·기대값을 따로 다시 세고,
누락된 종류·선택 번호·잘못된 집계·큰 정수 비교를 검사합니다.
저장 기록의 의미를 다시 확인하는 작업과 원래 프로그램을 재실행하는 작업의 범위는
각 결과에 따로 표시됩니다.
