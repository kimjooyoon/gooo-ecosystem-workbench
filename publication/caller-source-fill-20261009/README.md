# 여러 빈칸을 호출 결과로 고르는 실험 — 2026-10-09

조건식 하나와 변수에 넣을 값 하나를 함께 고르는 경로를 컴파일러에 연결했습니다.
예제는 다음 시도 예산을 계산합니다. 단독 함수 예제만으로는 세 후보를 구분하지
못했지만, 상한에 도달한 호출 결과를 추가하면 올바른 후보를 고를 수 있었습니다.

컴파일러는 깨끗한 `e115bb775e6a8a418dbb85eba13c16c606836f8f` 소스를
Go 1.27.1로 빌드했습니다. [빌드 정보](compiler-build.json)와
[고정한 계획](https://github.com/kimjooyoon/meta-ontology-go/blob/e115bb775e6a8a418dbb85eba13c16c606836f8f/examples/caller-source-fill/PLAN.md)을 남깁니다.
공개 0.6.13 바이너리에서는 이 경로가 지원되지 않았고
[그 오류](baseline-construct.stderr)도 보관합니다. 첫 예제 초안의 잘못된 문법은
[파서 오류](initial-fixture-parser.stderr)로 남겨 두었으며, 기대값을 바꾸지 않고
Gooo 문법으로 고친 다음 관측했습니다.

## 실제 실행

| 실행 | 조합 시도 | 별도 최종 평가 | 새 모델 예측 |
|---|---:|---:|---:|
| 예산 2회 | 2 | 1/4 | 0 |
| 예산 3회 | 3 | 4/4 | 0 |
| 예산 3회 기록 재실행 | 3 | 4/4 | 0 |
| 혼합 예제, 고정 순서 | 24 | 4/4 | 0 |
| 혼합 예제, 자체 모델 순서 | 3 | 4/4 | 1 |
| 혼합 예제 기록 재실행 | 3 | 4/4 | 0 |

두 관련 프로그램에 대해 새 조립 4번과 저장 기록 재실행 2번입니다.
재실행도 원래 시도 이력을 다시 구성합니다. 조합별 네이티브 실행은 재현성을 위해
내부적으로 두 번 실행되므로, 표의 조합 수와 프로세스 실행 수를 구분해야 합니다.
혼합 예제는 같은 예산 함수에 산술 레코드 선택을 붙여 조합을 늘렸습니다.
모델/고정 순서가 고른 소스는 같았고, 2^53을 넘는 정수 기대값도 그대로 비교했습니다.

[원본 JSON 압축 파일](../../examples/caller-source-fill/)과 [재계산 결과](summary.json)를
제공합니다. 아래 명령은 원래 평가 파일의 기대값과 실제 값을 정확한 JSON 숫자로
비교하고, 저장된 통과율을 다시 셉니다.

```sh
go run ./experiments/source-fill-observe
```

## 모델이 맡은 일

기존 `graph-chooser-20261008/all-data-demonstration/qat_ternary` 가중치를 그대로
사용했습니다. 메타데이터 SHA-256은
`3c68205a660695103712e2115ce90accd298b406dced8ad5ad5c9b84bab0a202`,
가중치는 `76f68845a03ed8c8bc261a57c919e96dcdd352d3c35bcdaeb3d9b51a88975c6f`입니다.
상주 텐서는 2,096바이트입니다. 모델은 레코드 선택 순서를 한 번 제안했고,
빈칸 묶음은 소스 순서로 탐색했습니다. 추가 학습은 하지 않았습니다.

이번 모델 예측 구간은 29,625ns, 약 0.030ms로 기록됐습니다. 전체 명령은
고정 순서 24.31초, 모델 순서 1.93초였고 최대 RSS 기록은 각각
87,621,632 / 87,605,248바이트였습니다. [고정 순서 기록](mixed-fixed.time)과
[모델 순서 기록](mixed-model.time)을 보관합니다. 같은 호스트에서 테스트가 함께
실행된 순차 관측이라 일반적인 속도 개선율로 사용하기 어렵습니다. CPU 전체
사용률과 유휴 기준값은 수집하지 않았습니다. 기록의 user/sys는 프로세스 CPU 시간입니다.

## Gooo가 다음 작업을 고르는 루프

작업장 소스 `9f12413`으로 Gooo 피드백 규칙을 실행했습니다. 정상 입력 하나로
시작해, 틀린 호출 사례 하나를 기대값 그대로 추가했습니다. 4회차에 걸쳐
1 + 1 + 2 + 3 = 7개 조합을 시도하고 멈췄습니다. 마지막 별도 평가는 4/4,
새 모델 호출은 0회입니다. 원래 사례·추가된 행·Gooo 판단·재실행 기록은
[루프 요약](joint-loop.json)과 [전체 관측 묶음](loop-observations.tar.gz)에 있습니다.

선택 점수에는 지역 학습 사례와 호출 사례만 들어갑니다. 소스의 별도 평가는
각 후보에서 측정하되 따로 보관합니다. 최종 평가도 선택이 끝난 뒤 실행합니다.
이번 결과가 설명하는 범위는 이 후보들과 사례들입니다. 다음 단계에서는 후보에
표현되지 않은 요구를 어떻게 드러낼지, 실패 사례를 바탕으로 어떤 표현을 추가할지
다뤄볼 수 있습니다.
