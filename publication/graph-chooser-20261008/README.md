# 소스 구조를 읽는 첫 자체 모델

Gooo에 선언한 부품 중 어떤 조합부터 시도할지 고르는 작은 모델을 Go로 학습했습니다.
파일명 처리, 정수 나눗셈, 재시도 판단이라는 세 프로그램을 사용했습니다.
각 프로그램에 여덟 요구, 여덟 후보 배치, 한글·영어·혼합 표현을 적용한 576행입니다.
프로그램 종류는 세 개입니다. 외부 사전학습 가중치를 사용하지 않았습니다.

## 학습 전에 정한 조건

[계획](../../experiments/graph-chooser/PLAN.md)은 결과를 보기 전
`5b0ee44d2e5896a8783cfc4c303a8671673be02a`에서 고정했습니다.
학습 코드 리비전은 `8503e279fe000f247cb4aa9bf2507c794a413a61`입니다.
공유 256→8→2 구조를 세 필드에 적용하며 매개변수는 2,072개입니다.
FP32 학습 400회, 추가 QAT 학습 200회, seed 20261008을 모든 분할에 적용했습니다.
전체 프로그램 하나를 제외해 384행으로 학습하고 나머지 192행으로 평가했습니다.
별도로 576행 전체를 학습한 시연용 모델도 만들었습니다.

## 첫 선택은 얼마나 맞았나

아래 값은 세 필드를 모두 맞힌 행 수입니다. 각 평가의 분모는 192입니다.

| 학습에서 뺀 프로그램 | FP32 | 학습 후 삼진 압축 | 삼진 QAT |
| --- | ---: | ---: | ---: |
| 파일명 처리 | 28/192 | 32/192 | 24/192 |
| 정수 나눗셈 | 16/192 | 24/192 | 10/192 |
| 재시도 판단 | 12/192 | 28/192 | 28/192 |

새 프로그램으로의 전이는 낮았습니다. 의도 문장을 가린 입력은 모든 분할에서
24/192였고, 기존 v1 모델은 명시적인 v1 입력 변환 후 전체 자료에서 72/576이었습니다.
기존 모델은 한 필드의 요구만 바꾼 864쌍에서 선택을 바꾸지 않았습니다.
전체 자료를 학습한 모델의 **학습 자료 내** 결과는 FP32·QAT 297/576,
학습 후 압축 159/576입니다. 이 수치는 새로운 프로그램에 대한 평가와 구분합니다.

각 행의 첫 선택, 요구 변경 쌍, 필드 일치 수, 의도 제거 결과, 학습 손실과
분할 명단은 `training-evidence.tar.gz`에 있습니다. 작은 요약은
[training-summary.json](training-summary.json)에 있습니다.

## 첫 선택이 틀려도 조립을 이어갈 수 있나

Gooo 0.6.9 개발판으로 세 프로그램 × 여덟 요구 = 24개 조립을 실행했습니다.
후보 배치는 하나로 고정했고 의도는 한영 혼합입니다. 비교 조건마다 같은
선언 사례 112건·336필드와 별도 실행 사례 128건을 사용했습니다.

| 시도 한도 | 결정론 순서: 완성한 조립 | 전체 자료 학습 QAT | 해당 프로그램 제외 QAT |
| --- | ---: | ---: | ---: |
| 1 | 3/24 | 5/24 | 2/24 |
| 2 | 6/24 | 16/24 | 5/24 |
| 4 | 12/24 | 23/24 | 10/24 |
| 8 | 24/24 | 24/24 | 24/24 |

8회 한도에서 실제 시도 수 합계는 각각 108, 63, 120입니다. 학습에 포함한
프로그램에서는 후보 순서가 도움이 됐고, 제외한 프로그램에서는 더 많이 시도했습니다.
시도 수와 실행 시간은 별도 지표입니다. 여기서는 전체 실행 시간 우위를 주장하지 않습니다.

1회 한도에서 선언 사례의 필드 충족 수는 각각 228/336, 256/336, 200/336입니다.
이처럼 일부 필드가 맞은 상태와 프로그램의 모든 선언 사례를 만족한 상태를 함께 기록합니다.
원본 소스의 사례 명단, 실제 출력, 독립 Go 계산, 분모를 대조하는 회귀 검사를 추가했습니다.

8회 한도에서 선택한 결과는 세 조건 모두 별도 실행 사례 128/128,
저장 재실행 128/128을 충족했습니다. 각 통과의 필드는 384개입니다.
고유 입력 묶음 16개를 여덟 요구에 반복 적용한 범위입니다.
모델은 조립마다 처음 한 번 호출됐고, 실패 후보 검사와 실행·저장 재실행에서
추가 호출하지 않았습니다. 예산별 탐색은 각각 독립 실행입니다.

`native-*-summary.json`은 분모와 시도 수, `native-*.tar.gz`는 소스·생성된 코드·
모델 식별자·실제 출력·저장 조립·각 예산의 부분 결과를 담습니다.
공개 회귀 검사는 세 조건의 72개 조립·72개 재실행·288개 예산별 기록을 다시 읽습니다.

## Gooo가 다음 작업을 판단한 결과

학습된 QAT 모델을 `feature-audit`에 직접 연결했습니다.
576개 입력은 구분됐고 첫 선택은 297개에서 라벨과 일치했습니다.
Gooo로 작성한 평가 함수가 `chooser-gap`과 `balance-candidate-training`을 반환했습니다.
즉 후보 배치와 프로그램별 학습 분할을 점검하라는 결과입니다.
[실제 관측](gooo-feature-audit.json)과 [평가 프로그램 실행](gooo-assessment.json)을 보관합니다.

## 크기와 실행 자원

- 삼진 모델의 가중치 파일은 446바이트입니다. 실행 시 텐서는 2,096바이트,
  행렬 스케일은 8바이트이며 JSON 메타데이터와 입력·실행 공간은 별도입니다.
- 다섯 삼진 값을 한 바이트에 저장하므로 행렬 가중치당 저장량은 1.6비트입니다.
  삼진 값의 이론적 정보량은 약 1.585비트이며, 편향은 FP32로 저장합니다.
- 준비된 입력 배열의 추론은 이 기기에서 행당 약 3.05~3.26µs였습니다.
  모델 로드와 Gooo 소스 분석·입력 변환·사례 검사는 제외한 구간입니다.
- Go 실행 준비와 전체 학습·평가 명령은 CPU에서 벽시계 3.81초,
  사용자 CPU 2.88초, 시스템 CPU 0.22초였습니다. 최대 RSS는 105,824,256바이트입니다.
  CPU 시간/벽시계는 코어 하나 기준 약 81%이며 호스트 사용률 상승분을 측정한 값은 아닙니다.
- 단일 기기의 한 실행입니다. GPU를 사용하지 않았습니다.

## 재현하기

저장소의 변경을 커밋한 상태에서 Go 1.27.1과 Gooo 0.6.9 개발판을 사용합니다.
새 출력 폴더를 지정합니다.

```sh
go run ./experiments/graph-chooser --out out/graph-training
go run ./experiments/graph-choice-corpus \
  --compiler /path/to/gooo \
  --expected-compiler 6c4a2b14f6f70c8efca4e08df4ac5e6ce572f9ff \
  --intent-contrasts --out out/graph-corpus
go run ./experiments/graph-choice-corpus \
  --compiler /path/to/gooo \
  --expected-compiler 6c4a2b14f6f70c8efca4e08df4ac5e6ce572f9ff \
  --native-contrasts out/graph-corpus \
  --native-model-folds out/graph-training --budget-probes --out out/graph-native
```

`--native-model`에 전체 자료 학습 모델을 지정하거나 모델 옵션을 생략하면 나머지
두 조건을 실행할 수 있습니다. 학습 자료를 만든 이전 컴파일러와 0.6.9로 다시 수집한
자료는 컴파일러 설명 문자열을 제외한 전체 입력이 같았습니다.
[대조 범위](corpus-release-equivalence.json)를 따로 기록했습니다.

CI는 공개한 12개 모델을 다시 로드해 행별 예측을 확인하고, 고정 계획으로 다시
학습한 가중치와 메타데이터를 공개 파일과 비교합니다. 추가로 세 프로그램에
해당 프로그램 제외 모델을 연결해 실제 조립·네이티브 실행·저장 재실행·예산별 탐색을 합니다.
학습 산출물과 Gooo 평가 결과는 CI artifact에 남깁니다.

## 다음 실험의 기준

입력을 구별하는 능력과 그 입력에서 올바른 선택을 배우는 능력 사이에 차이가 남았습니다.
다음에는 의도와 후보 연산의 관계, 세 필드 사이의 의존성을 살펴볼 예정입니다.
이번 세 프로그램을 개선에 사용하면 개발 자료로 취급하고, 새 프로그램을 별도 평가에
추가해야 합니다. 이번 결과를 보고 고정된 학습 조건을 다시 조정하지 않았습니다.

MIT 라이선스의 자체 코드와 자체 작성 자료입니다. 가중치는 이 GitHub 저장소에
포함했습니다. 이번 그래프 모델의 Hugging Face 업로드는 아직 완료하지 않았습니다.
