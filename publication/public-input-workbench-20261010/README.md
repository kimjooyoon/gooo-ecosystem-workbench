# 공개 입력 흐름과 작업장 연결

## 후보에서 직접 확인한 결과

`candidate90/`는 0.6.23 후보 컴파일러 `90bab730af14bef64e8378627450d3dd131967b3`과
설치된 작업장 `0d7d30a9e89576b4963e18b0967a71836849c234`의 원본 관측입니다.
공개 배포 소스 `2b17c4879d0bb2cd1e48ccc23b8743c0fb564267`과 생산자를 구분합니다.
후보 실행 파일을 공개 설치 파일로 바꿔 적지 않았습니다.

두 레코드 본문, 보조 함수, 별도 루트 입력을 연결한 `chain.gooo`를 사용했습니다.
최초 조립에는 자체 QAT 모델을 명시했고 다음 `construct`에는 모델을 생략했습니다.

| 단계 | 제공한 기대값에 대한 관측 |
| --- | --- |
| 최초 조립 | 모델 호출 2회, 호출 0/3, 필드 3/9, 본문 자체 필드 6/6 |
| 후속 조립 | 결정론적으로 7회차, 반복 포함 프로그램 시도 127회 |
| 조립 중 마지막 평가 | 필드 9/9, 조립에 사용한 호출 3/3 |
| 선택 뒤 별도 입력 | 원본 runtime 호출 2/2, 필드 6/6, 새 추론 0회 |

처음의 모델 순서만으로 호출 기대값을 만족하지 못했습니다. 후속 결과는 실제 실패 행을
Gooo가 다음 조립 조건으로 고르고, 후보 예산을 늘려 다시 조립한 뒤 얻었습니다.
`add-different-evaluation-inputs`는 평가 입력이 조립에 사용되었다는 Gooo의 판단입니다.
마지막 별도 입력은 선택 뒤에만 실행했습니다. 모델 학습 자료와의 독립성은 확인하지 않았습니다.

원본의 조립 시간 합계는 64.548초, 마지막 별도 입력 재생은 24.910초였습니다.
전체 명령 지연이나 모델 추론 지연으로 환산하지 않습니다.

## 원본 읽기

각 `.gz`는 원본 파일의 gzip 압축입니다. 모든 파일을 압축 해제해 원본과 바이트 비교했습니다.
`SHA256SUMS`는 공개 압축 파일의 체크섬입니다. 보고서 안의 원래 소스·모델·계획과 생산자 값도 유지합니다.

```sh
gzip -dc candidate90/workbench-model-initial/report.json.gz
gzip -dc candidate90/workbench-fixed-next/assembly-construction.json.gz
gzip -dc candidate90/workbench-fixed-next/construction/holdout-result.json.gz
```

마지막 파일의 `evaluation.runtime.finite_passed/finite_total`은 별도 입력의 호출 수입니다.
그 파일에 함께 보관된 `construction.caller`는 조립 때 사용한 호출 관측입니다.
회차별 원본도 보관하며, 모든 반복 시도의 합계와 고유한 후보 수를 구분합니다.
이 폴더는 관측을 읽는 데 필요한 원본 보고서 모음입니다. 실행 파일은 GitHub 릴리스에서 받습니다.
